# Shorter — Сервис сокращения ссылок

Консольное Java-приложение для сокращения длинных URL-адресов, управления ссылками и пользователями, а также автоматического контроля срока действия ссылок.

## Возможности

- Сокращение длинных URL-адресов.
- Генерация коротких уникальных идентификаторов.
- Перенаправление пользователя по короткой ссылке.
- Регистрация и управление пользователями.
- Привязка ссылок к пользователям.
- Настройка срока действия ссылок.
- Автоматическое удаление просроченных ссылок.
- Фильтрация и управление ссылками.
- Сохранение и загрузка данных в формате JSON.
- Отдельный файл конфигурации приложения.

## Технологии

- **Java** — основной язык разработки.
- **Maven** — сборка проекта и управление зависимостями.
- **Jackson** — сериализация и десериализация JSON.
- **NanoID** — генерация коротких идентификаторов.
- **JUnit 5** — модульное и интеграционное тестирование.
- **Mockito** — инструмент для создания mock-объектов в тестах.

## Требования

Перед запуском необходимо установить:

- JDK (проект проверялся на Java 26).
- Apache Maven.
- IntelliJ IDEA или другую Java IDE — по желанию.

Проверить установку Java и Maven можно командами:

```bash
java -version
mvn -version
```

## Установка и запуск

1. Клонировать репозиторий:

```bash
git clone https://github.com/nnhufg/url-shorter
```

2. Перейти в директорию проекта:

```bash
cd url-shorter
```

3. Собрать проект:

```bash
mvn clean package
```

4. Запустить приложение через IDE, выполнив класс `Main`, либо через Maven, если в проекте настроен соответствующий плагин запуска.

## Примеры использования

После запуска приложение предоставляет консольное меню.

Основные сценарии работы:

**1. Регистрация пользователя**

Пользователь регистрируется в приложении и получает уникальный идентификатор.

**2. Создание короткой ссылки**

Пользователь указывает исходный URL. Приложение генерирует короткий адрес вида:

```text
https://shrt.ru/aB12xY
```

**3. Переход по короткой ссылке**

При обращении к короткому адресу приложение находит соответствующую исходную ссылку и выполняет перенаправление.

**4. Управление ссылками**

Пользователь может просматривать и управлять своими ссылками, а также использовать предусмотренные приложением возможности фильтрации.

**5. Контроль срока действия**

Для ссылок может задаваться время действия. Специальный сервис периодически проверяет ссылки и удаляет просроченные записи.

```text

│           ├── controller/
│           │   └── ConsoleController.java
│           ├── models/
│           │   ├── Url.java
│           │   └── User.java
│           ├── repository/
│           │   ├── UrlRepository.java
│           │   └── UserRepository.java
│           ├── service/
│           │   ├── UrlShortener.java
│           │   ├── UrlShortenerService.java
│           │   ├── UrlPersistenceService.java
```

### Основные компоненты

| Компонент | Назначение |
|---|---|
| `Main` | Точка входа в приложение, создание и связывание компонентов |
| `ConsoleController` | Взаимодействие с пользователем через консоль |
| `models` | Модели данных пользователей и ссылок |
| `repositories` | Хранение и получение объектов в оперативной памяти |
| `UrlShortener` | Генерация коротких идентификаторов |
| `UrlShortenerService` | Основная бизнес-логика работы со ссылками |
| `UrlPersistenceService` | Сохранение и загрузка ссылок |
| `UserPersistenceService` | Сохранение и загрузка пользователей |
| `UrlExpirationService` | Автоматическая проверка срока действия ссылок |
| `AppConfig` | Загрузка и предоставление конфигурационных параметров |

### Принятые архитектурные решения

**1. Разделение на слои**

Логика приложения разделена на контроллеры, сервисы, репозитории и модели. Это упрощает сопровождение, тестирование и дальнейшее расширение проекта.

**2. Хранение данных**

Репозитории отвечают за работу с объектами в оперативной памяти. Для сохранения данных между запусками используется JSON-файлы.

**3. Сохранение данных через Jackson**

Jackson используется для преобразования Java-объектов в JSON и обратно. При сохранении применяется временный файл с последующей заменой основного файла, что снижает риск потери данных при прерывании записи.

**4. Генерация коротких ссылок**

Для генерации идентификаторов используется библиотека NanoID. Идентификатор состоит из шести символов латинского алфавита и цифр.

**5. Автоматическая очистка**

`UrlExpirationService` использует планировщик задач для периодической проверки срока действия ссылок.

**6. Конфигурация**

Параметры приложения вынесены в отдельную конфигурацию, чтобы не хранить изменяемые настройки непосредственно в бизнес-логике.

## Тестирование

Для тестирования используется JUnit 5.

В проекте реализованы два вида тестирования:

### Unit-тестирование

Проверяет отдельные компоненты приложения независимо от остальных частей системы.

Проверяются:

- корректность генерации коротких ссылок;
- соответствие домена короткой ссылки;
- длина генерируемого идентификатора;
- допустимые символы идентификатора;
- отсутствие повторений при генерации набора ссылок;
- корректность сохранения пользователей;
- корректность загрузки пользователей;
- обработка пустых и некорректных JSON-файлов;
- создание необходимых директорий;
- обработка некорректных входных данных.

### Интеграционное тестирование

Проверяет совместную работу нескольких компонентов приложения.

Реализован сценарий:

1. Создание репозитория пользователей.
2. Добавление пользователей в репозиторий.
3. Сохранение пользователей в JSON-файл.
4. Создание нового репозитория.
5. Загрузка данных из ранее сохранённого файла.
6. Проверка восстановления пользователей и их идентификаторов.

### Запуск тестов

Запустить все тесты можно командой:

```bash
mvn clean test
```

Для сборки проекта вместе с выполнением тестов:

```bash
mvn clean package
```

**Результат тестирования:** в проекте подготовлено не менее 15 тестовых сценариев, включающих модульные и интеграционные тесты.

## Структура хранения данных

Данные приложения сохраняются в JSON-файлах:

```text
data/
```

Файлы создаются автоматически при необходимости. Это позволяет сохранять информацию между запусками приложения без использования отдельной системы управления базами данных.
